# v0.27.9 治理 CLI 资源边界与进程生命周期根治方案

状态：正式当前方案；Engineering 仅实现本文件范围。内容存储/ContentDataArtifact 候选 004 不纳入本版本。

## 1. 唯一目标

治理命令必须可预测、可取消、资源有界、零隐式副作用。`--help`、未知参数和空命令不能扫描工作区；显式 inventory 超限或中断必须收口并留下最小可追溯事实，不能再次造成 runaway CPU/内存或孤儿进程。

## 2. 根因与边界

- 已确认：`scripts/content-lifecycle-governance.mjs --help` 会进入全量 inventory；inventory 保留大量 bytes/value/tokens 并构建引用图，缺少预算、取消和进程回收。
- 已确认：`scripts/content-storage-governance.mjs` 同样缺少参数早退和明确的重型命令合同。
- 工程责任：修复 CLI、inventory 算法、资源门禁、lease/取消/输出和 machine evidence。
- 外部责任：Codex/app-server 的 bounded timeout、取消传播、子进程树回收和启动来源调查；项目不得声称外部问题已修复。
- 不属于本版本：内容数据模型、ContentSet、ContentDataArtifact、ProductArtifact、SitePublication、页面、内容、清理迁移和线上发布。

## 3. 命令合同

1. argv 解析必须先于 workspace 访问、文件读取、写入和子进程创建。
2. `--help`、未知参数和空命令：O(1)、零 workspace scan、零读取、零写入、零子进程，并返回明确结果码。
3. 重型 inventory 只能由显式 subcommand/flag 启动；默认 `metadata-only`，`full-scan` 必须显式声明。
4. 完整 evidence 必须显式指定 `--output`；禁止帮助/诊断隐式写 ignored evidence、profile、cache 或原始 bytes。

## 4. 资源与算法合同

- full-scan 启动读取前必须固定且记录：`maxFiles`、`maxTotalBytes`、`maxFileBytes`、`maxWallMs`、`maxRssMb`/heap watermark、`maxOutputBytes`；缺失或无限值硬失败。
- 超限返回结构化 `partial`/`failure`，立即停止，不继续扩大；partial 不能作为清理、归档或删除依据。
- metadata→hash→reference graph 分阶段索引；逐文件/流式处理并施加 backpressure；禁止长期驻留全部 bytes/value/tokens 和无界 token×bytes/quadratic 匹配。
- 同一输入、模式和预算产生 deterministic records、hash、分类和摘要；metadata-only 不读取大文件正文。

## 5. 进程生命周期与证据

- 每次运行记录 `runId/owner/parentPid/processGroup/lease`，使用 `AbortController`。
- `SIGINT`、`SIGTERM`、timeout、cancel、父进程死亡和 lease 过期统一进入 `finally`：回收子进程组、lease、临时输出和句柄，不留 orphan。
- failure receipt 只保留 `runId`、阶段、failure code、停止原因、输入/预算摘要、必要 provenance；有界、原子写入。
- machine evidence 记录 `task/turn/command/runId/PID/parentPid/processGroup`、fixture/source hash、文件数、读取字节、峰值 RSS/heap、耗时、预算、停止原因、写入路径。
- Codex/app-server 依赖作为外部未决责任单独记录，不把项目测试结果转写为 OpenAI 已修复。

## 6. 强制验收 checklist

- `GOV-01`：help/unknown/empty 三类真实 subprocess 运行均为零扫描、零读取、零写入、零子进程、O(1) 有界退出。
- `GOV-02`：metadata-only 与显式 full-scan 分流；所有预算字段存在、有限、记录在 evidence；缺预算硬失败。
- `GOV-03`：空、小、大、损坏 JSON、symlink、半写入 fixture；流式/分阶段处理，无全量 bytes/token 驻留或 quadratic 匹配。
- `GOV-04`：超文件数、总字节、单文件、wall time、RSS/heap、输出大小均返回结构化 partial/failure，并立即停止。
- `GOV-05`：SIGINT、SIGTERM、timeout、cancel、父进程死亡、lease 过期均清理 process group/lease/temp，保留最小 failure receipt。
- `GOV-06`：重复运行相同 fixture/预算 deterministic；无 orphan、无隐式 ignored evidence、无超限输出。
- `GOV-07`：前后 Git、ContentSet、active pointer、SitePublication、受保护 `.content-workspace` 快照 path-set/bytes/hash 不变。
- `GOV-08`：evidence 具备真实 task/turn/command/PID/RSS/耗时/预算/停止原因/provenance；拒绝 placeholder、sentinel、伪造路径。
- `GOV-09`：任何 partial/failure/unknown reference 均不能进入 cleanup/archive/delete；治理 CLI 不默认触发内容发布或存储迁移。
- `GOV-10`：失败可回滚到当前稳定 tag；不修改 v0.27.8、旧 tag、内容事实、ContentSet、SitePublication 或线上状态。

Engineering 必须先完成 `GOV-01..GOV-10` 未提交自 QA 并回传证据；`elon` 逐项复核。任一项失败回同一版本修复，不得 commit/tag/build/preflight。全部通过后 `elon` 才能回传 `READY_FOR_COMMIT`。

## 7. 版本边界与后续关系

- 本版本只修治理 CLI/库和其测试/evidence 接口，不实现内容数据平面或旧派生物清理。
- 内容存储架构候选 004 后续仍须单独实现；其 inventory/清理必须调用本版本的显式、受预算约束 full-scan，partial/failure 一律保护。
- 本版本不触发 `elon ui`；不触发 `elon ops`；不执行 product transport、content publish、EdgeOne 或物理清理。

## 8. 禁止动作

不得再次运行 `scripts/*governance.mjs --help` 作为诊断；不得无预算 full-scan；不得终止未知进程；不得绕过 scope/checklist/READY 门禁；不得把进程停止、测试通过或报告生成称为根治完成。
