# v0.26.27 内容工作台页面导航即选择与局部预览方案

状态：正式产品方案

父版本：`v0.26.26` / `18c45c5ddc724c8e6d9be235c63b9a0867a52814`

## 1. Xing 的真实操作目标

工作台不能同时提供顶部页面下拉和右侧页面导航。两套入口会让 Xing 不确定“当前选择的页面”到底由哪一个控制。唯一自然的操作路径是：

```text
右侧真实页面的站点导航 → 切换当前页面 → 点击当前页面文字 → 左侧编辑 → 右侧即时确认
```

工作台仍是 canonical ignored content 的安全编辑与预览入口，不是新的 CMS，也不是产品站点的导航改造。

## 2. 页面交互结构

```text
本地编辑预览工具
────────────────────────────────────────
左：当前被点击内容的编辑器（独立上下滚动） | 右：真实页面 Web / Mobile（主要空间、独立滚动）
                                      └─ 使用页面自身的主导航选择页面
```

- 移除顶部“选择页面”下拉和页面选择帮助文案。
- 右侧两个 frame 都加载真实站点页面；站点主导航仍是页面选择的唯一入口。
- 桌面导航链接点击后由预览 frame 发送受控 `preview-navigation-click` 消息给父工作台；父工作台更新 `activeRoute`，同步替换两个 frame 的 route，不离开工作台。
- 移动端导航沿用站点自身菜单：打开菜单、点击同源注册 route 后同步两个 frame；工作台不复制一套移动菜单。
- 页面导航后清理旧 target marker、关系线和左侧 editor，再为新 route 请求可见 target；不保留旧页面内容造成误编辑。
- 右侧预览仍是主要空间；左侧上下滚动不影响右侧，右侧滚动不影响左侧和工作台导航状态。

## 3. 页面导航与正文选择边界

页面导航和内容 target 是两个不同对象：

| 行为 | 处理 | 是否写内容源 |
| --- | --- | --- |
| 点击主导航或同源注册页面 route | 发送 route-sync，两个 frame 同步 | 否 |
| 点击标题、说明、正文段落、列表项等 target marker | 发送 target-select，左侧加载 editor | 否，直到 Xing 保存 |
| 点击正文中的外部来源、媒体、Robotaxi CTA | 保持原页面行为，不由工作台代理 | 否 |
| 点击保存 | 对当前 target 做 source/value hash CAS 原子写入 | 只写 ignored canonical source |

内容 target marker 的优先级高于普通链接：如果同一元素是已登记内容 target，先进入 target 编辑；非 target 的同源页面链接才视为导航。外部链接、媒体和业务 CTA 不属于页面选择。

页面 route 只能来自现有 page definitions/注册页面白名单；不从 href 猜测未知页面，不把 query、锚点或外部域名写入 active route。

## 4. 与现有内容预览能力的关系

- `content/registry/content-targets.json` 继续是唯一内容白名单。
- `TargetImpact`、SSE、invalid/半写入/recovery、source/value hash CAS 和左右独立滚动保持 v0.26.26 合同。
- 页面导航只改变本地 preview route，不创建新的 session、不改变 target source hash、不刷新无关内容 frame。
- 正文编辑完成后仍由 Xing 将具体内容交给 `elon ops` 走独立内容 prepare/review/publish；页面导航和本次编辑不会触发产品 transport。

## 5. 失败和安全边界

- 不允许导航消息把工作台顶层页面跳走；只允许在两个预览 frame 内切换。
- route-sync 期间保留工作台 shell、编辑器列和预览列；旧 frame 关闭后再建立新 frame，失败时显示上一个有效页面并报告路由错误。
- 页面导航失败、未知 route、外部链接和 frame load error 都不能写入内容源或发布事实。
- 退出工作台后固定 4317 lease、PID、browser profile 和临时文件按现有规则清理。

## 6. 最小验收

1. 顶部无页面下拉；页面自身主导航可切换五类页面。
2. Web/Mobile 两个 frame 同步到同一 route；移动菜单可用。
3. 导航后点击正文 target 进入左侧 editor；不出现旧页面 target marker。
4. 正文修改只刷新真实受影响 frame，其他 route 不刷新；不全站 reload/build。
5. 左右独立滚动保持；active/review/recovery/release/SitePublication/ProductArtifact hash 不变。
6. 4317 固定端口一次真实 Xing 使用确认通过即可结束本版本工具验收；不进行无关的全站视觉复验。
