# v0.27.5 内容生命周期证据与发布门禁纠偏方案

## 定位

这是 v0.27.4 technical/evidence-contract 阻断的纠偏版本。复用 v0.27.0～v0.27.3 已实现的生命周期、changed-only、引用化 SitePublication 和 inventory 逻辑；只修复真实证据、validator 和收口门禁，不回写旧 tag。

## 目标

所有治理结论必须由本次真实运行、可追溯身份和 machine-readable evidence 计算。禁止 placeholder 或手写 PASS 造成 false-pass；官网数据、恢复链和历史审计事实保持不变。

## 实现范围

- `E-01`：建立两阶段 evidence identity。pre-commit 绑定 base HEAD、未提交 scope/diff digest、fixture/run provenance；`READY_FOR_COMMIT` 后绑定 exact annotated tag/tagCommit、ProductArtifact、artifactHash、baseSiteArtifactId、rootManifestHash。
- `E-02`：拒绝 placeholder、sentinel、delegated 文本和测试路径冒充结果；测试路径只能作为带 runId/commit/digest 的 provenance。
- `E-03`：真实执行 update/add/no-change，记录 scenario runId、fixture/source hash、before/after value/source hash、changed target、unchanged identity 和 Candidate/ChangeSet 结果。
- `E-04`：分开验证 atomic failure 与 same-publication resume/rollback，记录 PublicationRun、lease、outputRoot、deploymentId、active pointer 和 identity 结果。
- `E-05`：reducer/validator 依据字段 schema、来源证明和真实结果计算状态；禁止 truthy、手写 status、缺失字段或 `allowPending` 转为 PASS。
- `E-06`：release:prepare、closeout、preflight 和治理 CLI 使用同一 stage-aware validator；缺证据为 FAIL，未授权场景才可带理由 N/A。

## 验收清单

- `C-01`：pre-commit evidence 完整绑定 base HEAD、uncommitted scope/diff digest、fixture/run provenance；post-`READY_FOR_COMMIT` evidence 完整绑定 exact tag/artifact/root manifest。
- `C-02`：每个 evidence 字段有本次 run provenance；无 placeholder/sentinel/delegated/path substitution。
- `C-03`：update 为真实 changed-only，未变化 target identity/hash 不变。
- `C-04`：add 为真实新增 target，既有 target identity/hash 不变。
- `C-05`：no-change 不生成新 Candidate/ChangeSet/Snapshot/Publication 输入并复用 active identity；同一 ProductArtifact+ContentSet+manifest deterministic rebuild 同一 SiteSnapshot/hash。
- `C-06`：atomic failure 前后 path-set/bytes/hash、active pointer、Candidate/ChangeSet、PublicationRun/lease/outputRoot 和临时物均有真实证据。
- `C-07`：same-publication resume/rollback 复用同一 object/publication/deploymentId，重复执行幂等且 deployment 不增加。
- `C-08`：inventory/reference graph 可重跑且 deterministic；每条记录含 `logicalId/objectKind/namespace/state/bytes/hashMode/hash/sourceOfTruth/owner/retainUntil/decision/reason`，有四类分类摘要、current+2/retention decision、完整 root/reference graph、zero-action 和正向 archive fixture；未解析引用默认保护。
- `C-09`：SitePublication durable record 与临时 materialization 分离；legacy persisted outputRoot 默认保护；禁止持久全站复制，允许受控临时组装。
- `C-10`：pre-commit evidence → `elon` 逐项验收 → `READY_FOR_COMMIT` → commit/tag/build/preflight 两阶段门禁完整；exact-tag 条件只在 post-commit 生效。

## 不变边界

- 保留官网、canonical content/media、ContentSlotRegistry、active pointer/ContentSet、current+2 logicalContent revisions、review/recovery、当前 ProductArtifact source/dist、SiteSnapshot/PublicationRun/SitePublication、deployment/publicVerify、receipt/lineage/incident、lease 和 unknown refs。
- 不物理删除、移动、归档或迁移；不修改 v0.27.4 tag/history；不运行 content publish、product transport 或 EdgeOne。
- 不新增 CMS、第二套发布器或第二套生命周期模型。
- `DL-01`～`DL-03` 复用既有实现；`DL-04` 由 C-05～C-08 分别证明；`CL-05` 保持独立授权，不在本版本执行物理清理。

## 交付顺序

Engineering 先按本方案 checklist 自 QA 并回传未提交证据；`elon` 逐项复核。范围内问题回 Engineering 在本版本修复。全部通过后 `elon` 回传 `READY_FOR_COMMIT`，Engineering 才能 commit/tag/build/preflight；必要的 `elon ui`/内容分流通过后再按持续授权发布。
