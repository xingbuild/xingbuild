# v0.26.29 内容工作台预览源统一与目标级内容发布方案

状态：正式产品方案

父版本：`v0.26.28` / `7caf8eb66011302e04275cf928da4aa8644bdff4`

责任 owner：`elon`（产品与架构）；`elon engin`（实现与版本收口）；`elon ops`（内容确认、审核与独立发布）；`elon ui` 仅在本版本产生真实视觉/可访问性回归时介入。

## 1. Xing 本次要完成的工作

Xing 已经通过本地内容工作台修改了首页、Robotaxi 产品、经营观察长文和关于我内容。本轮先把这些修改按 source/hash/target 记录下来，不直接发布；产品能力修复完成并上线后，再由 `elon ops` 按既有内容工作流发布这批已确认内容。

本版本要解决的不是“再做一个编辑器”，而是两个发布链路事实必须一致：

1. 工作台看到并保存的内容，必须是内容发布 Candidate 实际读取的同一 canonical source；
2. 修改一个 target 只能更新它登记的 `consumerViews`，不能触发整页、全站、无关页面或整套 ProductArtifact 的更新。

## 2. 已发现的结构性问题

当前工作台在 `XINGBUILD_CONTENT_BUILD=1` 下读取被忽略的 `.content-workspace/content/home.json`，但内容发布生成器仍可能从 `src/content/siteContent.js` 读取 Home legacy fallback。这样会出现：本地预览已经改变，ContentSet Candidate 却读取另一份值，最终“发布成功但丢失首页改动”。

这是 source-of-truth 与发布入口的边界错误，不是文案错误，也不能用手工复制 JSON 或页面补丁解决。

## 3. 正式架构合同

### 3.1 两条链路，单向交接

```text
canonical ignored content source
        ↓
ContentPreviewSession / TargetImpact
        ↓
Xing 本地确认：before/after/hash/consumerViews
        ↓（仅记录，不改变 active）
elon ops：review → ContentSet Candidate
        ↓
Site Publication Coordinator：ProductArtifact + active/Candidate ContentSet
        ↓
公网验证后发布完成
```

- 预览链路只读/写 canonical ignored authoring source，并只刷新受影响消费者。
- 内容发布链路读取同一 source 的 normalized value/hash，生成一个 ContentSet Candidate；不读取 legacy fallback 作为 Candidate 输入。
- 预览不得写 `active.json`、review approval、ContentSet、ProductArtifact、SitePublication 或线上状态。
- 产品 transport 与内容 publish 仍是独立动作；产品版本上线不等于内容已发布。

### 3.2 Canonical source 与 Home 映射

- Home 内容发布 source 固定为 `.content-workspace/content/home.json`。
- `src/content/siteContent.js` 只允许在 product-only、无 active ContentSet 的本地运行 fallback 中使用，禁止进入 Candidate/ContentSet 发布输入。
- runtime Home、`home:home` entry、Candidate payload 必须来自同一个 normalized value 与 `contentHash`。
- practice、article、profile 等现有 source 继续沿用各自 canonical ignored source；不得为同一 target 建第二份可写事实。

### 3.3 Target 级差异更新

每次内容保存必须计算：

`targetId → sourcePath/fieldPath → normalized valueHash → consumerViews(route × viewport)`

- 只刷新 changed target 的登记消费者；同一 source 被多个页面使用时，刷新全部登记消费者。
- 无关 route/frame 的 URL、revision、DOM、滚动状态保持不变。
- 不触发全站 full reload、全站 build、ProductArtifact、SiteSnapshot、SitePublication 或 EdgeOne。
- 一个内容批次只形成一个 Candidate；未变化 target 复用 active identity，不制造重复 deployment。
- 无效/半写入/重复 ID/未登记 target/无法重现 source hash 时，保留 last-valid 并在 Candidate 写入前硬失败。

## 5. Engineering 实现范围

`elon engin` 只修改：

1. Home content adapter、content target registry 与 Candidate 生成入口，使 Home Candidate 唯一读取 `content/home.json`；
2. normalized value/hash/sourcePath/targetId/consumerViews 的统一校验与 machine evidence；
3. practice/article/profile/home 同批 Candidate 合并与 unchanged identity 复用；
4. Preview Runtime v2 的现有 target 级局部刷新、last-valid、SSE/session/lease/cleanup 能力的回归保护；
5. content prepare/build/reconcile/rollback 相关定向测试与 CLI 门禁；
6. 不破坏现有 `start-content-preview.command`、`start-xingbuild.command`、`publish-xingbuild.command`、`publish-content.command` 责任边界。

禁止：

- 修改公开页面 IA、视觉 token、稳定内容结构或现有 media/review 事实；
- 手工复制 Home 到 `src/content/siteContent.js`；
- 用全站重建掩盖 target 映射错误；
- 自动 approve、active、publish 或创建第二套内容发布引擎；
- 修改旧版本 tag/history、旧 SitePublication 或线上 deployment。

## 6. 必须通过的最小验收

### A. 预览到 Candidate 的同源性

- 故意让 `home.json` 与 `src/content/siteContent.js` 不同，Home prepare 仍读取 `home.json`；Candidate 的 `sourcePath`、normalized value、hash、route `/` 精确一致。
- Home source 缺失、非法 JSON、未登记字段、normalized hash 不一致时，在 Candidate 写入前失败且零落盘。
- 四个 target 同批变化只生成一个 Candidate；未变化 target 的 `entryId/contentHash` 不变。

### B. 局部更新

- 修改一个 target 后，只有其 `consumerViews` 的 Web/Mobile frame revision 增加；其他 route/frame 的 URL、revision、DOM 和滚动上下文不变。
- invalid、半写入、恢复和重复 ID 场景保留 last-valid；不发生全站 reload/build。

### C. 零写入与发布边界

- 预览与 Candidate 生成前后，active ContentSet、review/recovery/release、ProductArtifact、SitePublication 和线上状态保持不变。
- 产品版本完成后只执行一次既有 product transport；公网 product identity/runtime 通过后，才由 `elon ops` 消费本次已记录内容进入独立 ContentSet 发布。
- 任一 prepare/build/preflight/transport/publicVerify 失败立即停止，保留可恢复 evidence；不得绕过门禁、重试或新建第二 deployment。

### D. Xing 实际工作闭环

`start-content-preview.command` → 真实页面导航 → 选择 target → 编辑并即时局部预览 → 恢复/确认原文 → `elon ops` 读取同一 source/hash → 产品上线后按内容工作流发布。

- 内容发布成功与否必须单独回传 contentSet/sitePublication/publicVerify，不用产品版本号替代内容事实。
