# v0.26.23 全页面自然文本内容编辑工作台方案

状态：正式产品方案

## 1. 目标

Xing 可以在固定 `4317` 本地工作台中直接编辑网站内容，用自然文本和回车表达换行，立即看到真实 Web/Mobile 页面结果；内容确认后再由 `elon ops` 进入独立内容发布流程。

本能力覆盖注册表中所有 `editable=true` 的文本内容目标，而不是只覆盖 Robotaxi 说明；媒体 target 在同一工作台可见，但继续走媒体专用审核/替换流程并保持只读：

- `/`：首页定位、标题、说明和共享空状态；
- `/products`：Robotaxi 标题、说明、Why、模块字段和共享空状态；
- `/business-observations`：经营观察文章字段和共享空状态；
- `/observations`：每条观察的注册字段；
- `/about`：关于我字段；
- 动态 target：注册表模板展开出的 observation、module、media 等字段。

## 2. 根本设计

`responsive-text-slot-v1` 是发布/渲染的内部规范，不是内容作者的编辑格式。工作台不得要求 Xing 手写 `parts`、稳定 ID、projection 或 `breakAfter`。

```text
自然文本编辑器
  → 统一 authoring value
  → 内部响应式 slot 编译器
  → target validator
  → TargetImpact
  → 受影响页面 Web/Mobile frame
```

内容作者只看到文本、回车、Web/Mobile 预览和错误提示；内部 slot 结构由系统自动生成。

## 3. 编辑规则

### 3.1 默认统一文案

一个文本框中的内容同时作为 Web 与 Mobile 的语义来源。回车表示作者明确要求的段落/换行；没有回车的部分由浏览器按容器宽度自然换行。

### 3.2 响应式差异

只有当 Xing 明确选择“移动端单独换行”时，工作台才显示 Mobile 断点编辑器。两端必须保持同一连续文本，不能形成两份互相漂移的文案；系统只保存各 profile 的断点位置。

### 3.3 非响应式字段

普通字符串字段使用同一自然文本编辑器；如果页面组件不支持显式换行，工作台显示自然换行预览，不伪造页面结构能力。

### 3.4 所有 target 统一入口

工作台从 `content/registry/content-targets.json` 读取静态 target 与模板实例，按页面、对象和字段分组。不得维护第二套字段清单或页面映射。

## 4. 写入与生命周期边界

- 只允许写入当前 target 对应的 canonical ignored content source；写入采用 source hash CAS 和原子替换；
- 无效 JSON、空值、超长、未知 target、越界 fieldPath、projection 不一致在写入前拒绝；
- 自动保存只代表本地 preview draft，不代表审核、批准、active 或发布；
- 媒体字段不通过文本 authoring 写入；工作台只展示其 mediaId/asset 状态，媒体替换仍由既有媒体审核流程负责；
- 不写 `src/`、schema、CSS、组件、`active.json`、ContentSet、review、recovery、release、ProductArtifact、SitePublication、deployment 或 EdgeOne；
- 关闭工作台不生成产品版本、不生成 ContentSet、不触发发布。

## 5. 局部刷新

每次编辑由 target registry 与 page definitions 解析 `TargetImpact`：

- 只刷新发生变化的 target 的 consumer routes/views；
- 其他 route、frame、URL、DOM、revision 和导航计数保持不变；
- 不使用 JSON 全量 reload、全站 build 或隐式 Vite HMR 作为业务协议；
- invalid/半写入保留 last-valid 页面并显示字段级错误；恢复有效值后只恢复受影响 frame。

## 6. 页面与内容独立性

该能力只增加“内容编辑入口”和“内容值编译”能力，不改变任何页面 IA、布局、组件组合、视觉 token、媒体归属或页面生命周期。首页、`/products`、经营观察、观察详情和关于我仍分别拥有自己的页面投影；共享的只是注册 target、内容解析器、基础渲染器和局部刷新协议。

## 7. 验收

一次能力验收覆盖所有页面域，而不是每次文案修改都要求 `elon ui` 重做全站验收：

1. 从工作台选择每个页面域至少一个 target，输入自然文本并回车；
2. Web1280/Mobile390 真实 frame 立即显示对应内容；
3. Products intro 等多消费者 target 只刷新 `/` 与 `/products`；About、观察、经营观察和首页独有 target 不刷新无关页面；
4. Web/Mobile 特殊断点只影响对应 profile；
5. invalid、半写入、恢复和 source hash CAS 均可观察；
6. active ContentSet、review/recovery/release/SitePublication/ProductArtifact 前后 byte/hash 不变；
7. 4317 lease、PID、浏览器 profile/temp 正常清理。

`elon ui` 只对工作台本身做一次产品/视觉能力验收；日常内容编辑不重复触发全站视觉验收。

## 8. 明确不做

- 不新增 CMS、数据库、第二套 target registry 或第二套页面内容源；
- 不要求 Xing 直接编辑 JSON；
- 不把 Web/Mobile 文案复制成两套独立事实；
- 不因内容本地编辑自动 build、commit、tag、ProductArtifact、ContentSet 或线上发布；
- 不删除、迁移或清理历史发布证据；
- 不修改已发布产品版本的页面结构或内容事实。

## 9. 工程交付边界

Engineering 需要实现：authoring value 编译器、全 target 清单/分组、工作台编辑面板、source hash CAS 原子写入、响应式断点编辑、统一错误/恢复状态、TargetImpact 局部刷新和全页面域真实使用证据。

产品完成后，Xing 的日常流程只有：

```text
选择页面字段 → 直接输入文字 → 回车换行 → 本地确认 → 交给 elon ops 发布
```
