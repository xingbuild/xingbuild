# v0.26.28 本地内容工作台结构化正文、差异更新与产品化入口方案

状态：正式产品方案

父版本：`v0.26.27` / `e15fa851d2a34f891d254403b0f3559902ad4c93`

## 1. Xing 的真实目标

Xing 需要一个可以反复使用的本地内容工作台：在真实页面中选中内容，在左侧直接修改，在右侧立即确认；确认后的内容可以交给 `elon ops` 按既有内容生命周期审核和发布。

这个工具必须满足三个系统约束：

1. 内容修改只影响明确的 `targetId` 与其 `TargetImpact.consumerViews`，不触发全站刷新、全站构建或 ProductArtifact/ContentSet/SitePublication。
2. 回车是可理解、可保存、可发布的内容语义，而不是只在 textarea 中暂时存在的视觉假象。
3. 工作台是项目内可直接启动的固定工具，不需要每次询问 task 才能找到入口；它与普通本地网站启动、产品发布、内容发布保持不同入口。

## 2. 根因与边界

当前 v0.26.27 已有目标影响面和局部消费者刷新，但存在四个真实问题：

- 普通字符串正文只能保存字符串，回车不会自然形成结构化段落；关于我和常青长文的正文因此可能“保存了换行但页面看不出换段”。
- 输入事件自动保存与“保存并预览”按钮共存，第二次保存可能只显示“内容未变化”，不能清晰表达第一次自动保存已经完成。
- 当前工作台仍有桌面关系线；页面导航和内容高亮已经足以完成定位，关系线是重复信息。
- 预览已有脚本入口，但没有根目录一键工作台入口；普通 `start-xingbuild.command` 与内容预览入口的责任需要明确分开。

已有 `content-rich-text-list-v1`、`responsive-text-slot-v1` 和 `TargetImpact` 是本版本唯一复用的能力，不另建第二套内容发布引擎。

## 3. 正式内容表达合同

### 3.1 三种 authoring value

| 类型 | 使用场景 | 回车含义 | 发布形态 |
| --- | --- | --- | --- |
| `string` | 标题、短标签、链接、单段短文 | 保留为同一字符串；不承诺视觉分段 | 原有字段，不迁移既有事实 |
| `content-rich-text-list-v1` | 关于我正文、常青长文正文段落 | 每个非空行成为一个结构化段落 | 兼容旧单字符串，保存后形成字符串数组 |
| `responsive-text-slot-v1` | Hero 说明、模块说明、Why 等需要 Web/Mobile 投影的文本 | Web/Mobile 各自的登记断点 | 维持现有 parts/projection/breakAfter 合同 |

`content-rich-text-list-v1` 必须兼容旧的单字符串源：读取旧字符串时作为一个段落；写入出现回车的内容时才形成数组。没有内容修改时不迁移、不改写源文件。

### 3.2 页面覆盖

- `/about`：About 的正文 block 与结构化 item description 支持段落编辑。
- `/business-observations`：企业经营体系长文 paragraph/lead/callout 文本支持段落编辑。
- `/observations` 与单篇观察：继续复用已有 rich-text-list 段落；普通标题、摘要和证据字段保持 `string` 语义。
- `/products` 与首页：继续复用现有 responsive text 与普通字段；不因本版本改变页面 IA、组件组合或视觉合同。

### 3.3 身份安全

内容 block/item 的 `id` 必须在其源数组内唯一。重复 id 不得被 `.find()` 静默解析成第一个对象；工作台应给出明确的 ambiguous target 错误并停止写入。重复 id 的既有内容元数据由 `elon ops` 作为一次内容事实修正处理，不由产品代码自动改写。

## 4. 差异更新合同

```text
canonical ignored source
        ↓
targetId + valueHash/CAS
        ↓
TargetImpact.consumerViews（route × viewport）
        ↓
仅刷新受影响的本地预览消费者
```

- 保存响应必须记录 `targetId`、before/after valueHash、变化类型（文本/段落/响应式断点）和实际刷新 consumerViews。
- 无变化时不得写源文件，不增加 revision，不刷新任何 frame。
- 有变化时只刷新该 target 登记的 route×viewport；其他路由、其他 frame、工作台 shell 不刷新。
- 不触发 Vite 全局 HMR、全站 full reload、产品 build、ProductArtifact、ContentSet、SitePublication、EdgeOne 或线上状态变化。
- 这里的“局部”以注册 target 的消费者为边界；不为每个页面另建私有刷新逻辑。

## 5. 工作台交互合同

- 移除关系线，只保留右侧真实页面中的 target 高亮、左侧编辑器和受影响页面说明。
- 输入编辑器支持结构化正文：回车预览为段落，空行、非法控制字符和超长内容明确拒绝。
- 自动保存与手动保存必须有清晰状态：自动保存成功显示“已保存本地预览源”，点击按钮无新差异显示“当前已是最新”，不能把二次保存误报成丢失。
- 修改后立即更新右侧受影响页面；保存状态明确区分“本地已写入”“未审核”“未发布”。
- 页面导航仍由右侧真实站点导航承担；正文 target 选择与页面导航保持独立。

## 6. 产品化启动入口

新增根目录可双击入口：

```text
./start-content-preview.command
```

它只做以下事情：

1. 使用当前 canonical main/worktree、当前 HEAD、`XBUILD_TASK_ID=elon` 和固定 4317 lease 启动 `content-preview` mode。
2. 自动打开 `http://127.0.0.1:4317/__xingbuild/content-preview`。
3. 若 4317 已被同一内容预览 session 占用，则直接复用并打开；若被普通网站或未知进程占用，明确停止，不终止未知进程、不静默换端口。
4. 退出时清理 preview lease、PID 和临时 profile/cache。

现有入口保持不变：

- `./start-xingbuild.command`：普通产品网站本地预览，不进入内容编辑工作台。
- `./publish-xingbuild.command`：产品 ProductArtifact transport；不发布内容、不自动 build、不修改版本。
- `./publish-content.command`、`./publish-article.command`、`./publish-practice.command`：`elon ops` 内容发布意图；仍须经过审核、ContentSet 和 Coordinator。

本版本不把工作台保存直接连接到任何 publish 命令。

## 7. Engineering 实现边界

`elon engin` 只修改：

- content authoring/compiler/decompiler 的 rich-text-list 兼容与正文 renderer；
- content target registry 的正文类型、重复 id 硬失败与 target impact 证据；
- dev-only workbench 的关系线移除、保存状态、差异摘要和固定启动入口；
- 对应定向测试、启动脚本静态门禁和文档入口。

禁止修改：

- 产品站点 IA、公开页面视觉、ContentSet active 指针、review/recovery/release、已发布内容事实；
- `publish-xingbuild.command` 的产品 transport 语义；
- `elon ops` 的审核、内容事实和发布状态；
- 通过全站 rebuild 或第二套 content publish engine 绕过 `TargetImpact`。

## 8. 验收合同

1. 双击 `start-content-preview.command` 可在固定 4317 打开内容工作台；普通 `start-xingbuild.command` 与三个 publish 入口仍通过现有语义检查。
2. About 与经营观察正文回车后，右侧显示真正的多个段落；刷新工作台后内容仍存在；普通单字符串字段仍不被强制迁移。
3. 重复 block/item id 在编辑前明确报错，不静默修改错误对象。
4. 修改一个 target 后，仅其登记 consumerViews 更新；无关 frame 的 URL、revision、DOM 与加载状态不变；不触发全局 full reload/build。
5. Web/Mobile responsive slot 的现有换行、Products Why、CTA、媒体和安全外链保持不变。
6. 保存证据包含 before/after hash、targetId、changed parts/paragraphs、consumerViews、sourceRestored/zero-write 边界；active ContentSet、review/recovery/release、ProductArtifact、SitePublication 和线上状态保持不变。
7. Xing 使用一次完整闭环：启动工具 → 右侧选择页面 → 点击正文 → 回车分段 → 右侧确认 → 重新打开确认 → 恢复原文；通过后才进入产品版本收口。

## 9. 版本与责任

- `elon`：本方案、产品边界和验收合同。
- `elon engin`：实现、测试、VERSION/history、commit/tag/clean、exact build/preflight。
- `elon ui`：仅当工作台出现真实可访问性或视觉回归时独立复核；不重复整站视觉验收。
- `elon ops`：内容 block id 元数据修正、内容审核和后续 ContentSet 发布；不修改产品代码。
- Xing：一次实际使用确认；产品/视觉验收通过后沿用既有持续授权决定 product transport，内容发布仍独立进行。
