# v0.28.0 内容数据平面与内容增量发布架构方案

状态：正式当前方案；Engineering 仅实现本文件范围。
来源候选：`XBUILD-CONTENT-STORAGE-ARCHITECTURE-004`（已由 `elon1` 只读复核 PASS）。

## 1. 唯一目标

建立三层分离的内容发布架构：`ProductArtifact` 只承载产品能力，`ContentDataArtifact` 只承载内容数据，`SitePublication` 只保存两者引用和发布结果。内容小改不重建产品、不复制未变化内容或完整站点；旧派生物清理是实现后的独立迁移结果，不是无界删除目标。

## 2. 当前问题与边界

当前 active 指针只指向 `ContentSet`，代码尚无 `ContentDataArtifact` 或独立 runtime reader；内容发布路径仍可能以 `assemble: true` 组装完整 client，并持久化重复 materialization。v0.27.9 的有界治理 CLI 已是 inventory/dry-run/清理的唯一入口，但不等于内容数据平面已实现。

本版本不改页面 IA、视觉、正文、媒体事实或上游事实；不新增 CMS、第二发布器或并行 worktree；不在未授权下物理清理、transport 或 content publish。

## 3. 目标架构

```text
canonical content/media → revision → ContentSet → ContentDataArtifact
                                      ↓                 ↓
                         elon ops 审核/批次       runtime data manifest

Product source/schema/renderer → ProductArtifact ───────┘
                                  ↓
                    SitePublication = 两者引用 + 最小 receipt
```

1. 内容数据平面由 canonical `.content-workspace/content`、`ContentSet` 和 `ContentDataArtifact` 组成。每条记录必须有 `logicalContentId`、`revisionId`、`predecessor`、`schemaVersion`、`sourceHash`、`valueHash`、`status`。
2. `ContentDataArtifact` 有固定 schema、artifact identity/hash、对象 manifest 和 source/ContentSet provenance；active 以 `contentSetId/contentSetHash/contentDataArtifactId/contentDataHash` 原子 tuple 切换，校验失败保持旧 active。
3. 每个 `logicalContentId` 保留 current 与前两次 revision（最多 3 个）；更早 revision 只有在无引用、无 lease、无迁移/恢复任务且有 retention 证据时才可处理。
4. `ProductArtifact` 提供内容读取与投影能力，产品 client 不内嵌内容事实。运行时读取 active data manifest，使用 immutable data URL 和明确缓存策略。
5. 内容-only 发布只写变化的 ContentDataArtifact 对象、active tuple 和最小 receipt，复用现有 ProductArtifact 的 JS/CSS；平台需要的完整上传包只能是临时 staging/upload-root，不得持久化为新产品身份。
6. `ContentSet` 仍是 `elon ops` 的审核/运营身份；`ContentDataArtifact` 由 Coordinator 从已确认 ContentSet 派生；Ops 不直接写 CAS、ContentDataArtifact 或 active tuple，不新建发布器。
7. 持久 receipt 只保留 schema/version/commit、ProductArtifact 与 ContentDataArtifact 身份/hash、ContentSet、activePointerHash、siteSnapshot/sitePublication、run/deployment/publicVerify、failure/recovery 摘要和证据 hash；历史完整 client/source/snapshot 不默认保留。
8. 逻辑身份与物理 materialization 分离；相同 namespace、logical identity、字节 hash 只保存一份，hash 不替代 provenance。

## 4. 必须实现的行为

- 相同 canonical `ProductArtifact + ContentSet + manifest` 重复运行复用 ContentSet、ContentDataArtifact、ProductArtifact、SiteSnapshot 和 immutable object identity；显式再次部署只允许新增最小 `PublicationRun/deployment` receipt。
- 单一 target 更新只生成变化 revision/ChangeSet/ContentDataArtifact 对象和受影响 `consumerViews`；未变化 entry、媒体、route identity/hash 复用；ProductArtifact build count 为 0，JS/CSS identity/hash/bytes 不变。
- no-change 不生成新的输入、ContentDataArtifact 对象或 ProductArtifact；失败、取消、激活失败保持旧 active tuple，并保留最小 failure/recovery receipt。
- 新发布、预览和验证只依赖当前 source、Git/ProductArtifact manifest、active ContentSet 和 ContentDataArtifact，不依赖旧 SitePublication、releases、旧 dist 或旧 outputRoot。
- preview/build/staging/upload/QA 的 lease、进程、profile、outputRoot 和临时目录在成功、失败、SIGINT、超时后清理；inventory/dry-run/清理必须复用 v0.27.9 有界 CLI，partial/failure/unknown/预算不足不得作为清理依据。

## 5. 强制验收 checklist

- `SA-00`：真实 revision 字段、current+2；schema/adapter 变化 fixture deterministic，保留 predecessor/source/value hash/schemaVersion，迁移失败不改 active/current。
- `SA-01`：核验 source-of-truth、active ContentSet、ProductArtifact、ContentDataArtifact 的 schema、manifest、provenance、identity/hash、原子 tuple 与公网 deployment。
- `SA-02`：相同 canonical 输入不因 previousContentSetId、createdAt 或 runId 生成新身份；显式再次部署仅新增最小 receipt。
- `SA-03`：单 target 只更新变化对象与受影响 consumerViews；未变对象/媒体/路由 identity/hash 不变，ProductArtifact 不构建。
- `SA-04`：临时物、lease、进程和 profile 无孤儿；具备 immutable URL、缓存策略、两阶段部署/激活、失败回退和同 deployment recovery 证据。
- `SA-05`：receipt 符合固定 schema、只保留引用/摘要、无 dangling reference；历史记录只保留最小 identity/provenance，物化字节删除前有引用根和 migration cutover。
- `SA-06`：物理清理是独立显式授权迁移；只处理超出 current+2 且 unreferenced/unleased/reconstructible 对象，保护 unknown/external/current publication/registry/active/current+2/ProductArtifact/必要 receipt。
- `SA-07`：清理后仅凭当前 source + Git/ProductArtifact manifest + active ContentSet + ContentDataArtifact 可重建、验证和发布。
- `SA-08`：固定 fixture/run/build counter/路由/manifest/media/cache，连续 identical/partial/no-change 证明 object count/bytes/hash delta；禁止按 run 线性复制整站，partial 时 ProductArtifact build count=0。
- `SA-09`：内容-only 发布保持 ProductArtifact、JS/CSS identity/hash/bytes 不变，并完成受影响路由、manifest、media、cache 公网验证。
- `SA-10`：post-action inventory 记录保留/删除对象、bytes、hash、reference、retention；重复清理安全 no-op，不删 failure/recovery receipt 或 Git 追溯。
- `SA-11`：浏览器从未变化 ProductArtifact 读取新的 ContentDataArtifact 可见更新；激活失败不污染页面。

实现前同步 `AGENTS.md`、`docs/rules/engineering-architecture-and-principles.md`、`docs/rules/iteration-and-release.md`、`docs/rules/responsibility-and-workflows.md`、`docs/rules/collaboration-workflow.md`、`docs/operations/内容运营与发布规则.md` 和产品总案：统一为 `ProductArtifact + ContentDataArtifact`，ContentSet 是 Ops 数据身份，不是每次发布都嵌入完整 client 的构建物。不得改写 v0.27.9。

## 7. 完成边界与顺序

Engineering 必须先按 `SA-00..SA-11` 完成未提交自 QA；`elon` 逐项复核并回传 `READY_FOR_COMMIT` 后才可 commit/tag/build/preflight。任一项失败回同一版本修复，不扩张范围。产品架构实现通过后，清理仍需 Xing 另行授权；未授权不得删除、迁移、quarantine、transport 或 content publish。

实施顺序：

1. 数据对象、CAS、ContentDataArtifact、runtime reader 和原子 active tuple；
2. ContentSet/ChangeSet 接入内容-only发布，复用 ProductArtifact，建立临时 materialization 与最小 receipt；
3. failure/recovery、缓存、两阶段激活和完整 SA 证据；
4. 只读 inventory/dry-run，待授权后再分批迁移/清理并完成公网验证。
