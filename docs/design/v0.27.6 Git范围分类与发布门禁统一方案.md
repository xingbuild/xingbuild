# v0.27.6 Git范围分类与发布门禁统一方案

## 定位

修复“commit 只含产品实现、build 却要求全局 Git clean”的范围混用。Git 提交范围、ProductArtifact 运行输入和 Content/Ops 生命周期必须分离。

## 必须实现

- `V276-01`：每版本生成 `docs/iterations/scopes/v{版本号}.json`，记录 pre-commit `baseHead`、`scopeDigest`、逐路径 `classification`、`owner`、`reason`、`pathHash`、`state`；manifest 自身为 `record-only`，不进入自身 digest。
- `V276-02`：唯一 classifier 扫描 staged、unstaged、deleted、renamed、untracked，分类仅允许 `implementation`、`record-only`、`excludedExternal`；自 QA 阶段允许 manifest 已声明且 state=added 的新路径暂未 staged，未知 untracked 即 `unclassified`/硬失败；READY 后 closeout 必须要求声明路径全部 staged。
- `V276-03`：owner 已确认的 `implementation + record-only` 必须同一次 commit/tag；`record-only` 进入 Git/history，不进入 ProductArtifact 运行输入；`.content-workspace` 继续走独立 ContentSet。
- `V276-04`：`excludedExternal` 必须有 tracked owner/reason，不豁免 dirty；未知 untracked、未确认、未分类和未收口 external 一律阻断；禁止目录或名称默认放行。
- `V276-05`：closeout、release-build、preflight、unified-publish 共用 classifier；禁止直接用全局 `git status` 一概阻断；classifier 只替代 dirty 判断，不削弱 annotated tag、HEAD、版本、ProductArtifact 和 manifest 门禁。
- `V276-06`：pre-commit 校验 `HEAD=baseHead`；post-commit 将 `committedHead` 写入独立 machine evidence，校验 `firstParent(committedHead)=baseHead`、声明路径已进入 commit、scope digest 未漂移；不得回写 tracked manifest。

## 验收 checklist

- `C276-01`：implementation 与 record-only 可同次收口；ProductArtifact 运行输入不含 record-only。
- `C276-02`：未知 untracked、manifest 缺失/漂移、路径重叠、owner/reason 缺失均硬失败；自 QA 对已声明 added 路径允许暂未 staged，READY 后 closeout 对其 staged 状态硬校验。
- `C276-03`：added/modified/deleted/renamed 的 pathHash/state 计算可重现。
- `C276-04`：pre/post phase 身份正确，无 committedHead 自引用 dirty。
- `C276-05`：四个 gate 使用同一 classifier，输出分类清单和阻断原因。
- `C276-06`：exact annotated tag、HEAD、VERSION、current、ProductArtifact identity 仍全部校验。
- `C276-07`：重复执行 deterministic、无额外 commit、无 ProductArtifact/ContentSet/SitePublication 写入副作用。
- `C276-08`：既有 v0.27.5 lifecycle evidence、Content/Ops ignored 内容和 active ContentSet 保持不变。

## 不做

不改页面、内容事实、ContentSet、SitePublication、发布目标或历史 tag；不执行物理删除、迁移、content publish 或 EdgeOne transport；不新增第二套发布器或生命周期模型。

## 交付门禁

Engineering 先按本 checklist 自 QA 并回传未提交证据；`elon` 逐项复核并回传 `READY_FOR_COMMIT`。此前不得 commit/tag/build/preflight。通过后 Engineering 一次性提交全部已确认 tracked 变更，再执行 exact build/preflight；持续发布授权有效时，门禁通过后按既有 Coordinator 流程 transport。
