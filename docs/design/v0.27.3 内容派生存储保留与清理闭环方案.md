# v0.27.3｜内容派生存储、保留与清理闭环方案

版本：`v0.27.3`
父版本：`v0.27.2 / ae0befadc177e049380795c948109ddd31d7c13d`

## 目标

保留当前官网、active ContentSet、当前内容/媒体和恢复审计；让内容小改只复用未变化对象，不再长期复制持久 SiteSnapshot；建立可重跑、零写入、可恢复的历史派生物治理。ProductArtifact 独立治理，发布时允许临时组装。

## 已完成边界

v0.27.0～v0.27.2 已完成 `ContentRevision`、`ChangeSet`、changed-only 复用、canonical `sourceHash`、无变化 ContentSet 复用和 reference-only SitePublication durable record。本版本不重复实现这些逻辑，只补齐物理存储、保留、迁移、清理和恢复闭环。

## 实现范围

| itemId | 必须实现 | 结果 |
| --- | --- | --- |
| `SG-01` | 锁定 active pointer/ContentSet、ContentSlotRegistry+registryRevision、current+2 logicalContent revision、current draft/review/recovery/incident、当前 SitePublication/ProductArtifact source/dist、receipt/lineage、过渡期 package、canonical content/media 为保护根 | 当前官网与未来内容发布不受影响 |
| `SG-02` | 提供可重跑 inventory 与引用图；root manifest 覆盖全部配置根/保护根；记录 logicalId、objectKind、namespace、source-of-truth、hash、bytes/count、state、owner、incoming/outgoing refs、lease、`retainUntil`、restorePath、rebuild proof、decision/reason | 未知对象和未解析引用默认保护 |
| `SG-03` | 输出 `keep/review/archive-dry-run/delete-never` 分类、原因、对象数量和可释放空间；区分 durable record/provenance 与可重建 materialization | 清理前可审查 |
| `SG-04` | 按 object namespace 使用 immutable CAS；hash 不替代 logical identity/provenance/lifecycle；迁移支持旧路径双读与回滚 | 未变化对象不重复落盘 |
| `SG-05` | 分离 `/tmp` staging、`/tmp` upload-root、persisted `site-publications` outputRoot；成功记录只保留 finalized reference；失败/recoverable 保留 recovery/evidence | 发布后不长期保留完整站点副本 |
| `SG-06` | 每个 `logicalContentId` 保留 current+2；draft/review、ProductArtifact、ContentSet、releases、publication、audit/recovery、QA/cache 分别定义窗口与 owner | 历史不无限累积 |
| `SG-07` | 清理执行器校验 lease/进程、外部引用、授权 scope、quarantine manifest、restore test、retention window；先 dry-run，分批授权后才可归档/删除 | 不误删、可恢复、可重复执行 |

## 明确不做

- 不改 UI、IA、schema、正文、媒体、review 语义或 active ContentSet 内容事实。
- 不新增 CMS、第二套 ContentSet、第二套发布器或全站业务重建流程。
- 不自动删除；未知引用、未证明 owner、active/current/recovery/incident/hold 对象默认 `delete-never`。
- 不回写 v0.27.2；不在本版本自动 content publish、product transport 或 EdgeOne。

| checkId | 必须有的结果证据 |
| --- | --- |

## 实现顺序

1. 只读 inventory/reference graph 与 protected-root baseline；先证明零写入。
2. 实现 namespace CAS、持久记录/临时物分离、旧路径双读和回滚。
3. 实现 retention policy、quarantine/archive dry-run 和清理门禁；不执行物理删除。
4. 加入 failure-injection、restore、resume、重复运行和 update/add/no-change 回归。
5. 生成 AC-01～AC-14 machine evidence，完成 local/staged 验收；任何缺证据停止。
6. 只有 Xing 对 dry-run 和恢复证据确认后，才执行分批物理清理；清理后重新 inventory 与收口审计。
