# v0.27.4 内容存储治理证据门禁修复方案

## 定位

这是 v0.27.3 的纠正版本。v0.27.3 的存储治理代码已提交，但其 evidence acceptance 存在 false-pass：证据未绑定精确制品、inventory 只有 metadata hash、引用图未解析、AC 状态可由固定文字直接标 PASS。因此 v0.27.3 不作产品/架构通过，不回写旧 tag。

## 目标

让每个治理结论都由可复核事实计算；缺证据、不一致或未执行只能是 `FAIL`/有理由的 `N/A`，不得声明 PASS。只读盘点、可恢复边界和未来清理决策必须可重复、可审计。

## 实现范围

- `E74-01`：evidence 顶层绑定 `version`、精确 `commit`、annotated `tag`、`ProductArtifact`、`artifactHash`、`baseSiteArtifactId`、source/root manifest hash。
- `E74-02`：新增 acceptance reducer/validator；AC 状态只由真实字段、引用和场景证据计算，禁止 unconditional PASS；`N/A` 必须有未授权/未执行原因。
- `E74-03`：inventory 明确 `full`/`metadata` 模式；候选归档或删除必须使用逐字节 SHA-256，metadata-only 只能 `review`/`delete-never`；重复运行 path-set、bytes、hash、summary 必须确定。
- `E74-04`：引用图解析 node/edge 和 incoming/outgoing refs，覆盖 active、registry、lineage、receipt、recovery、incident、lease、SitePublication、deployment、publicVerify；未解析引用默认保护。
- `E74-05`：明确 durable record、persisted outputRoot、临时 staging/uploadRoot 的边界；没有迁移、部署、恢复证明，不得把 persisted materialization 判为可归档。
- `E74-06`：以真实 machine evidence 覆盖 update/add/no-change、failure injection、原子失败、同对象幂等恢复、zero-action/no-action；可复用旧证据时必须有精确身份引用，不能写 delegated 代替证据。
- `E74-07`：release:prepare、closeout、preflight 和治理 CLI 使用同一 validator；证据缺失或不一致硬失败。保留历史/环境型 QA failure，不隐藏、不修饰。

## 明确不做

本版本不物理删除、移动、归档或迁移任何历史对象；不修改 active ContentSet、官网内容、媒体、review/recovery、SitePublication、线上部署；不运行 content publish、product transport、EdgeOne；不改 UI/IA/schema。

## 强制验收清单

- `AC74-01`：evidence identity 与 exact HEAD/tag/ProductArtifact 完全一致。
- `AC74-02`：保护根 manifest 覆盖 canonical、active、registry、ContentSet、receipt、lineage、recovery、incident、release、publication、artifact、QA 与 lease，并保存 path-set/hash。
- `AC74-03`：full inventory 可重跑；每条记录有 logicalId/objectKind/state/bytes/hashMode/hash/retainUntil/sourceOfTruth；候选对象为逐字节 hash。
- `AC74-04`：引用图 node/edge 可解析；外部 deployment/publicVerify/lease 和未解析引用均有结果，未解析默认 delete-never。
- `AC74-05`：dry-run 前后所有扫描根 path-set、bytes、hash、Git status、进程/lease、工具副作用均证明零写入。
- `AC74-06`：CAS 验证字节相等、namespace/version 隔离、ref-count、旧路径双读和失败回滚。
- `AC74-07`：current+2 仅按 logicalContentId；audit/incident/hold/legacy/unknown 默认保护；各 namespace retention 可解释。
- `AC74-08`：durable record 与 persisted/temporary materialization 分离；无迁移/部署/恢复证明不得归档 outputRoot。
- `AC74-09`：无变化时复用 active identity，不生成 Candidate/ChangeSet/Snapshot/Publication 输入。
- `AC74-10`：update/add/no-change 逐项证明 changed-only、未变对象 identity/hash 保留；引用 v0.27.2 证据必须 exact identity。
- `AC74-11`：注入失败清理临时物、active pointer 不变、无半状态；失败可重复且幂等。
- `AC74-12`：同一对象/发布恢复复用原 identity；未运行场景标记有理由的 N/A，不得以文字声明 PASS。
- `AC74-13`：未获生产授权时 production publish 明确 N/A；若获授权，必须分开记录 assets/app/media/publicVerify 完整证据。
- `AC74-14`：结束时生成 post-action inventory、保护 identity、scope digest/count/bytes、quarantine/restore 结果；zero-action 也有 machine evidence。

## 交付证据

固定证据：`.content-workspace/qa/v0274-storage-governance/evidence.json`。必须包含 validator 输出、AC 状态、identity、inventory/reference graph、场景结果和零写入证明；不得修改 v0.27.3 证据或旧 tag。
