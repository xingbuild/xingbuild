# v0.26.24 页面化内容编辑与对应预览工作台方案

状态：正式产品方案

## 1. 目标

Xing 打开本地工作台后，先按页面理解内容，再在左侧编辑，右侧看到同一页面的真实结果。工作台要让 Xing 始终知道“我正在改哪个页面的哪个区域”，并在修改后立即看到对应页面变化。

日常内容流程是：

```text
选择页面 → 选择页面区域 → 左侧输入自然文本 → 右侧实时预览 → Xing确认 → elon ops独立发布
```

这是一项 dev-only 内容作者体验改进，不是 CMS、产品页面改版或发布链路重构。

## 2. 页面分类

页面分类由现有 `content/registry/content-targets.json` 与 page definitions 推导，不维护第二套字段清单：

| 页面分类 | 路由范围 | 说明 |
| --- | --- | --- |
| 首页 | `/` | 首页定位、首页标题、首页作品说明与首页专属文案 |
| B端产品 | `/products` | Robotaxi 标题、说明、Why、模块文字与产品入口 |
| 经营观察 | `/business-observations` | 经营观察页眉、栏目和文章投影 |
| 观察文章 | `/observations` 及其详情路由 | 观察标题、摘要、证据边界等注册字段 |
| 关于我 | `/about` | 关于我页面注册文本字段 |

动态观察详情仍归入“观察文章”，不会为了工作台复制一份内容模型。

## 3. 左侧编辑与右侧预览

工作台采用两栏结构：

- 左侧是当前页面的字段导航和内容编辑区；字段显示页面语义名称、targetId、当前值类型、可编辑/只读状态和影响路由。
- 右侧是同一 target 的真实 Web1280/Mobile390 页面 frame；不是静态 mock，也不重新实现页面渲染。
- 一个 target 影响多个页面时，右侧显示全部真实 consumer views，并在每个 frame 标明路由和视口。
- 媒体字段继续可见但只读，显示 mediaId/asset 状态，替换媒体仍走既有媒体流程。

## 4. 对应关系

选中左侧字段后：

1. 左侧字段卡变为 selected；
2. 右侧真实页面中对应 DOM 区域出现高亮边界和 target 标识；
3. 工作台在左侧字段卡与右侧目标区域之间绘制关系线；
4. 一个字段有多个 consumer view 时绘制多条线，并显示对应路由/视口；
5. 切换字段、页面或视口后，旧高亮和旧关系线立即清除。

关系线只存在于本地工作台，不写入页面源码、不改变线上 DOM、不进入产品构建物。目标区域通过已登记 target 的当前值和页面 consumer identity 定位；无法定位时显示“预览区域未定位”，不得误标其他内容。

## 5. 编辑与响应式规则

- Xing 只输入自然文本和回车，不直接编辑 `parts`、`projection`、`breakAfter` 或 JSON。
- 默认 Web/Mobile 共用一份语义文本，浏览器自然换行。
- 只有明确打开“移动端单独换行”时，才显示 Mobile 编辑区；系统仍保存同一语义文本与 profile 断点，不复制两份事实。
- 输入草稿更新右侧本地预览；保存使用 source/value hash CAS 和原子替换。
- invalid/半写入保留 last-valid 页面并显示字段级错误；有效恢复后只刷新受影响 frame。

## 6. 精准刷新与生命周期边界

TargetImpact 仍是唯一影响面事实：

- 只刷新当前 target 的真实 consumer route×viewport；
- 其他页面、frame、URL、DOM、revision 和导航计数不变；
- 不触发全站 reload、全站 build、ProductArtifact、ContentSet、SitePublication 或发布；
- 预览只写 `.content-workspace/content/**` 当前 source；active ContentSet、review/recovery/release、ProductArtifact、SitePublication、deployment 和 EdgeOne 均只读。

## 7. 工程实现边界

Engineering 只改 dev-only `content-preview` workbench 与其测试：页面分类推导、字段导航、两栏布局、frame 目标定位、高亮关系线、TargetImpact 局部刷新和零发布副作用。不得改产品页面 IA、布局、视觉 token、内容 schema、媒体审核、ContentSet 或 SitePublication。

## 8. 验收合同

1. 打开固定 `4317` 后无需知道 targetId，首页出现页面分类；
2. 进入每个页面分类至少选择一个 target，左侧显示该页面字段，右侧显示同页真实 frame；
3. 选中字段时右侧目标区域高亮，至少一条可见关系线连接左右；多消费者 target 的每个 consumer view 都能对应；
4. 修改并保存自然文本后，右侧只刷新受影响 frame，输入结果可见；无关页面不刷新；
5. Web/Mobile 特殊换行、invalid、恢复、CAS 冲突和媒体只读状态保持现有合同；
6. active ContentSet、review/recovery/release/SitePublication/ProductArtifact 前后 byte/hash 不变；
7. 固定 4317 lease、PID、profile/temp 正常清理；
8. `elon ui` 对本工作台能力做一次独立体验验收即可，日常内容编辑不触发全站视觉复验。

## 9. 明确不做

- 不新增 CMS、数据库、第二套 target registry、第二套内容源或第二套 renderer；
- 不将页面编辑变成产品页面结构编辑；
- 不在每次内容输入后执行全站 build、commit、tag 或线上发布；
- 不让内容工作台写入 active ContentSet、review、release 或 SitePublication；
- 不删除或迁移历史发布证据。
