# v0.27.1 内容生命周期真实链路收口方案

父版本：v0.27.0 / `2e4c72a1c5bfc04501b758b4c70b30d42d5ecdfe`
来源：v0.27.0 产品验收发现的真实链路缺口
contentImpact：compatible；不改变页面、内容事实或线上身份。

## 必须收口

- `V271-01`：现有 `ContentRevision`/`ChangeSet` 必须接入真实 content target → ContentSet Candidate/prepare 链；一次内容修改只生成变化 target 的 revision/ref，未变化 entry identity/hash 原样复用。禁止仅保留独立 helper。
- `V271-02`：现有 deterministic snapshot 与 reference-only SitePublication 必须接入真实 `site-publication`/Coordinator 持久化链；长期记录不得嵌入完整 `siteSnapshot`、assembled client 或临时 upload root，运行证据另存引用。
- `V271-03`：inventory 必须保守处理未知引用；released/recoverable/failed SitePublication、receipt、lineage、recovery、lease 一律 `delete-never` 或 `keep`，不能因未扫描到引用进入 archive-dry-run。dry-run 仍零写入、不可删除。
- `V271-04`：修正 v0.27.0 记录事实：候选已归档转换，DL/CL 已实现但未发布；不得把它写成“仍为 DRAFT、未进入 Engineering”。

## 不变边界

- 不改页面 IA、组件、视觉、schema、正文、审核、media、active ContentSet 或线上状态。
- 不新增 CMS、第二套发布器、数据库或事件系统；复用 v0.27.0 已有生命周期模块和唯一 Coordinator。
- 不执行物理删除、迁移、content publish 或 product transport；先完成真实链路证据。

## 验收

1. 通过真实 target/ContentSet prepare 证明 changed-only 与 unchanged identity/hash 复用。
2. 通过真实 SitePublication assembly/readback 证明只存引用，完整 client 只在临时目录。
3. 同一 ProductArtifact + ContentSet + manifest 真实重建 snapshot/hash 一致。
4. inventory 两次结果一致；未知引用、released/recoverable/failed/lease 对象均不进入可归档动作；dry-run 前后保护 hash 不变。
5. 旧 v0.27.0 不回写；新版本记录、测试、exact tag/build/preflight 完整。
