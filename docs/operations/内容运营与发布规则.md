# 内容运营与发布规则

## 1. 责任边界

内容与发布 task 是独立运营责任域，负责：

- 事实审核、来源边界和内容 Brief；
- B 端产品页面文案与模块数据；
- Observation、Article、Practice 内容对象；
- 用户确认、内容发布包、内容发布和公网内容验收。

产品与视觉负责页面结构、IA、schema、组件、交互、视觉合同和产品版本。Engineering 负责产品能力与产品版本实现。Ops 只生成可信证据候选、去重和覆盖记录，不写公开正文、不审核、不发布。

### 1.1 采集与调度禁区

内容 task 只能消费已存在的 `EvidenceCandidate`、Ops 检查点或用户明确提出的按需采集结果；不得执行定时采集，不得创建、复制、更新或替代 `xingbuild` 自动化、cron、scheduled task 或 Ops 采集 task。无候选时只报告“无候选，等待下一步”，不得用创建调度器作为补救动作。

需要补充事实时，内容 task 只能把按需采集请求交给已登记的 Ops 长期责任 task `019fd012-6699-7b90-aadf-c2da6b097644`；找不到目标、发现重复调度器或责任不明时，立即报告用户并停止，不得自行创建或猜测目标。

## 2. 内容对象生命周期

```text
事实/来源 → Draft → Review → 用户确认 → Approved → Published → 公网验收
                         └──────────────失败保留 draft/review/recovery
```

- Draft、Review、Recovery 和采集运行记录只写被忽略的 `.content-workspace/`。
- 已确认内容才可形成正式内容发布包。
- 发布失败不得删除 draft、review 或 recovery，不得写入产品完成历史。
- 通过产品设计确认后，内容对象不转成产品候选；只有能力或结构缺口才转产品候选。

内容进入 `Approved` 且已有本批次授权后，内容 task 默认自动完成 prepare、build、transport、public verify、finalize，不重复向 Xing 询问；只有 Xing 明确暂停、停止、撤销或要求人工接管时才停止。未确认内容、身份不一致、事实/审核/hash/网络等硬失败仍必须停止并上报。

## 3. B 端产品页面内容

当前目标页面是 `/products` 的 Robotaxi 运营平台，使用既有：

```text
ShowcaseLayout → PracticePage → SystemStage → approved media
                                  └────────→ Observation rail（有有效内容时显示）
```

内容 task 可确定：

- Hero 标题、短说明和事实边界；
- 当前模拟、城市空间迭代、经营模型、经营总览等模块的表达；
- 每个模块的读者问题、单一结论、事实证据、`mediaId`、`loopRelation` 和 `action`；
- 页面 CTA 与继续阅读路径。

内容 task 不可修改页面结构、路由、组件、schema、CSS、交互能力或上游业务事实。

## 3.1 快速定位与方案写作

内容 task 不再从整站重新研究开始。唯一入口是机器可读注册表：

`content/registry/content-targets.json`

它登记 `targetId`、`sourcePath`、`fieldPath`、受影响路由、可编辑白名单和事实/媒体门禁。数组对象只能按稳定 `id` 定位，不能按当前文案、DOM selector 或数组顺序猜测。

### 3.1.1 最短读取路径

```text
AGENTS.md → 00-baseline-index.md → 本文件
→ content/registry/content-targets.json → 目标内容对象
→ 必要的来源/媒体文件
```

定位唯一且已登记时，不重复读取产品总案、页面组件、历史 task 或 xAI 页面。只有注册表缺失、页面能力变化或事实边界无法判断时，才补读产品总案/页面实现，并在报告中说明扩大读取的原因。

### 3.1.2 一次定位卡

内容 task 的第一条有效回复只需给出：

```text
目标：targetId / scope
位置：sourcePath#fieldPath
当前：beforeHash + 当前值摘要
影响：projectionRoutes
可改：登记字段与约束
不可改：路由、结构、schema、组件、CSS、业务/上游事实
方案：after 值或明确字段批次
需要确认：仅列一个真正未决问题；无歧义则直接请求确认
```

用户确认后才形成被忽略的 `.content-workspace/changes/` ChangeSet 并进入既有 `content:prepare`、`content:build` 和独立 transport。简单内容工作不需要额外 ACK、重复交接、轮询或再次提交同一研究结果。

`scope=page` 只表示多个明确字段组成一次内容批次，不允许整文件覆盖；`scope=module` 只表示已登记模块的明确字段集合。

### 3.1.3 内容工作与候选分流

标题、简介、模块说明、已登记 CTA/链接、已批准媒体和事实边界内的表达，直接由内容 task 写方案，不产生产品候选。只有以下情况才停止并登记候选：

- 目标未登记，且需要新增页面、字段、模块或改变页面结构；
- 需要修改路由、IA、schema、组件、CSS、交互、业务逻辑或共享视觉能力；
- 现有内容 CLI、媒体合同或 transport 无法安全执行；
- 来源、事实边界或媒体公开资格无法验证。

首页是内容运营范围的一部分。v0.26.0 必须先把 `src/content/siteContent.js` 的 `description`、`homeTitle` 和空内容文案迁移为登记的 `home` ContentSet entry；迁移完成后，内容 task 可按同一 ContentSet 流程修改首页公开文案，不得直接修改 `src/`。在迁移完成前，首页文案请求暂存为 Candidate/待能力完成，不得绕过入口直接改 `src/`。`site.name`、导航标签、页面结构和组件组合仍属于产品能力，不属于日常内容字段。

第一阶段复用现有内容发布命令，不新建第二套 `content:plan/preview/approve/publish/rollback` 发布引擎；只有现有命令无法消费已确认 ChangeSet 时，才提出工具能力候选。

研究对象：[`x.ai/cli`](https://x.ai/cli)、[`Build overview`](https://docs.x.ai/build/overview)。只学习表达方法：

```text
单一 Hero 价值主张

```

## 3.3 本轮内容确认顺序

```text
页面读者与目标
→ Hero 标题/短说明/边界
→ 模块顺序与每模块单一结论
→ 事实证据与 mediaId
→ loopRelation 与 action
→ CTA 与继续阅读路径
→ 桌面/手机展示验收
```

每个模块先写“读者问题、单一结论、事实来源、证据媒体、边界、行动”，再写最终公开文案；没有用户确认的内容不得进入 Approved。

## 4. 研究参考边界

xAI CLI 页面（`https://x.ai/cli`）只用于研究：

- 单一 Hero 价值主张；
- 能力模块分组；

- 清晰 CTA 和由浅入深的阅读节奏。

不得复制 xAI 文案、品牌、图片、产品事实或技术承诺。Robotaxi 的事实必须来自 Robotaxi 上游事实和已批准媒体。

## 5. 内容发布身份

内容运营不创建或递增产品 `v0.x`。日常内容运行身份是不可变 `ContentSet`：

```text
contentSetId / contentSetHash / entryId / target / contentHash
sources / reviewProof / mediaProof / route
```

旧 `contentReleaseId` 只作为 `legacyAuditId` 保留，不能参与 active、替换、predecessor 或发布判定。产品版本、`current.md`、`VERSION.md`、产品 history、commit/tag 和产品 publish 不属于内容发布状态。

内容发布只生成 ContentSet Candidate 与对应 ContentDataArtifact，物理站点 transport 统一交给 Site Publication Coordinator：

v0.28.3 起，Candidate、ContentDataArtifact、产品制品和 candidate tuple 必须由唯一 `ContentPublicationIntent` 绑定；`content:prepare`/`content:build` 只生成 intent，不 transport 或写 active。Coordinator 在固定站点 lease 下完成 release/content/data manifest、immutable object、首页文案与浏览器 runtime 的同一 PublicationRun proof，随后才以 CAS 写 `content-data-active.json`。legacy `content-state/active.json` 只读用于首次 baseline，不得双写。

```bash
npm run content:prepare -- --target <target>
npm run content:build -- --candidate <contentSetId>
./publish-content.command --candidate <contentSetId>
```

运行事实位于 ignored 工作区：

```text
.content-workspace/content-state/sets/<contentSetId>/content-set.json
.content-workspace/content-state/active.json
.content-workspace/content-state/data-artifacts/<contentDataArtifactId>/content-data-artifact.json
.content-workspace/content-state/content-data-active.json
```

`content:prepare` / `content:build` 读取已审核正文、来源和媒体 proof，生成确定性的 ContentSet Candidate 与 ContentDataArtifact；不创建逐条 active slot、lineage、projection 或 deployment 状态。`publish-content.command`、`publish-article.command` 和 `publish-practice.command` 只提交 Candidate/ContentDataArtifact intent 给 Coordinator；Coordinator 选择当前稳定 ProductArtifact，以既有 site-snapshot-v1 组装引用，内容-only 变化只物化临时 upload root，唯一调用 EdgeOne，并验证整站公网 manifest、目标页面/媒体后才原子切换 active data tuple。内容 task 不 push、commit、tag、修改产品版本文件或直接调用 EdgeOne。

已审核但尚未上线的内容只能进入 Candidate，不自动成为 active。失败保留 Candidate、review、recovery 和 AuditLog；旧 active ContentSet 不变。网站可见但没有同一 PublicationRun 的完整公网证据，按工具失败处理。

内容与产品可以独立准备，但 physical transport 不能并行；产品更新复用 active ContentSet 与 ContentDataArtifact，内容更新复用当前 ProductArtifact，未变化对象通过 CAS/hash 复用。

内容独立发布能力完成前，内容 task 只进行内容确认、schema/事实检查和本地预览；不得绕过产品工程能力，也不得自行部署。

## 6. 内容发现能力缺口

- 文案、顺序、事实、媒体或 CTA 问题：内容 task 直接修正内容对象。
- 新增页面、路由、模块类型、schema、组件、交互或数据能力：停止内容操作，报告产品与视觉 task，由产品版本流程处理。
- CLI、工具或发布能力故障：停止本次运营操作，形成 Incident 并报告；能力修复进入产品工程版本，不在内容 task、main 或私有分支自行修复。

### 6.1 能力建设与能力使用

- 使用已经实现的内容对象、ContentSet builder、校验和独立 transport 修改公开文案：属于独立内容运营，使用 `contentSetId`，不递增产品版本。
- 新建或修改字段级 `ChangeSet`、ContentSet schema、ContentSet builder、目标解析、内容发布 CLI、媒体合同、content slot capability 或 transport 合同：属于产品工程能力建设，必须写入 `current.md`，由 Engineering 按产品版本闭环实现、提交、验收和发布。
- 内容 task 只能报告能力缺口和证据，不能把能力建设混入一次内容发布，也不能自行修改 `scripts/`、`src/`、schema 或产品版本文件。
- 能力建设完成并通过产品/视觉验收后，日常内容才回到独立内容运营；能力发布本身不改变日常内容的独立身份。

## 7. 固定报告

每次内容 task 收口必须报告：

```text
内容目标 / 目标对象 / 已确定内容 / 未确定内容
事实与来源 / schema 与媒体检查 / 本地预览
contentRelease 状态 / 公网状态 / 阻断 / 下一动作 / 用户需要确认什么
```

无候选、无阻断时必须明确写出“内容状态已闭环，等待用户下一步”。
